#   As dez divergências C3/C4/C5 que AOS-198 registou aqui foram RECONCILIADAS, não

#
# Regra de honestidade desta baseline (mantida para futuras entradas):
#   1. Toda a entrada TEM de trazer `owner=` — o gate falha se faltar. Além disso,
#      o `owner=` TEM de nomear um ticket `AOS-NNN` que EXISTE e está ABERTO: o gate
#      extrai o ticket, resolve o seu `### Estado` e falha se for inexistente,
#      indeterminado ou já fechado (uma dívida de contrato não pode ter por dono um
#      ticket que já fechou sem a reconciliar).
#   2. Toda a entrada TEM de dizer o que o código faz HOJE em vez do que o contrato
#      manda (nome real, ou ausência real).
#   3. A baseline só ENCOLHE, nas duas direcções: (a) quando o código passa a
#      declarar o código de porta, a entrada fica OBSOLETA e o gate FALHA até ser
#      removida; (b) quando o par contrato|código deixa de existir em `tecnica/12` —
#      contrato removido, código renomeado, parágrafo «Semântica de erro»
#      reformatado — a entrada fica ÓRFÃ e o gate FALHA também. Sem (b), uma entrada
#      que nunca mais é visitada torna-se permanente em silêncio, que é exactamente
#      o caminho pelo qual esta regra deixaria de ser verdadeira. Provado nos
#      self-tests §N2 (obsoleta) e §N5 (órfã).
#   4. Uma divergência NOVA (contrato ou código a mudar) NÃO entra aqui sem passar
#      pela mesma revisão: o gate bloqueia primeiro.
#
# O que a baseline NÃO afirma: que uma divergência é benigna.
#

# Chave de comparação: `contrato|CÓDIGO` (o pacote é informativo).
