# O que o proxy de produção entrega ao gateway para cada forma de resposta (AOS-508)

> Data: 2026-10-07. Corrida única do gate opcional `ci-wire-live` (`scripts/ci/wire-live.sh`,
> teste `TestAOS508_ProxyReal_OQueOProxyEntregaACadaCaso`), em local, com Docker.
>
> **Imagem do proxy:** `ghcr.io/berriai/litellm@sha256:154e23bb5f31b1f10e16392a8ef299bd2cde08de3a64a6849002cfcc25ce3c63`
> (a de produção, LiteLLM 1.96.2, pelo digest).
>
> **O que foi medido.** Um provider falso atrás do proxy devolve cada um dos 87 casos de
> `packages/platform/model-gateway/internal/wirefake/casos`; o proxy é configurado com uma rota
> `openai/…` por caso (`drop_params: false`, sem repetições) e recebe um pedido de chat sem
> tools. Para cada caso compara-se o corpo que o falso mandou com o corpo que o proxy entregou.
> As colunas de forma são as da ficha do AOS-507 (`port.ProbeResponseShape`), calculada sobre os
> dois corpos. A última coluna é o que o gateway faz ao corpo entregue, depois do AOS-509.
>
> **O que NÃO foi medido.** O provider real não foi contactado: nada aqui diz que formas o Kimi
> manda. Só a rota `openai/…` (a de produção); outro adaptador do proxy traduz de outra maneira.
> O pedido não levava `tools`. É uma corrida, numa versão do proxy.

## 1. O que o desenho marcava como não verificado, e o que se mediu

| Pergunta (desenho A2 §2.4 e §9) | Medido |
|---|---|
| Que nome dá o proxy ao raciocínio? | `reasoning_content` passa como veio (string). **`reasoning` em string é RENOMEADO para `reasoning_content`** (a chave `reasoning` desaparece). **`reasoning_details` e `thinking` são RETIRADOS** e não chegam em campo nenhum. `thinking_blocks` em lista passa com o mesmo nome. Com `reasoning_content: null` presente, o `reasoning` que o acompanha é retirado e não chega raciocínio nenhum |
| O proxy reescreve `content: null`? | Não: `null` chega `null`, `""` chega `""`, só brancos chega só brancos. `content` AUSENTE passa a `content: null` |
| O proxy acrescenta `provider_specific_fields`? | Sim, em `message`, em 63 dos 64 casos entregues |
| `content` em lista de partes | **O proxy responde 500** nos dez casos (só texto, várias, parte vazia, lista vazia, com tool call, com imagem, com recusa, sem `type`, tipo desconhecido, `text` que não é string), e também com `content` em número ou em objecto. O gateway não chega a ver a resposta |
| `function.arguments` em objecto | **O proxy entrega-os como STRING** (os dois casos em objecto chegam com `arguments` em string). Em lista ou número, o proxy responde 500 |
| Raciocínio em objecto ou lista (`reasoning_content`, `reasoning`) | O proxy responde 500. `thinking_blocks` em string ou objecto também; em lista passa |
| `refusal` | **É retirado.** O caso H5 chega com `content: null` e mais nada: indistinguível de H6 depois do proxy |
| `message.function_call` (forma antiga) | Passa como veio, com o `finish_reason` que trazia (`stop` ou `function_call`); o proxy não o converte em `tool_calls` |
| Várias `choices` | Passam as duas; a resposta que está na segunda continua na segunda |
| `finish_reason` fora do mapa | **É normalizado pelo proxy**: `end_turn`, `STOP`, ausente e `null` chegam `stop`; `tool_use` chega `tool_calls`. O gateway nunca vê o valor bruto por esta rota |
| Ids de tool call | Passam como vieram (`call_…`, `functions.<tool>:<n>`, numérico em string, UUID, de comprimento fixo, repetido, vazio). **Ausente: o proxy inventa um UUID.** Um id em NÚMERO JSON passa como número, e o gateway recusa a resposta (`json_invalido`) |
| `usage` ausente | O proxy acrescenta um objecto `usage` |
| Assinaturas (`thinking_blocks[].signature`, `thought_signature` na tool call) | **Não medido nesta corrida.** Os blocos em lista passam com o mesmo nome, mas a medida não regista se a chave de assinatura chega; fica por acrescentar |

## 2. Consequências para a fase A2

1. **Hipóteses do `empty_output` depois do proxy.** H1 (texto em `reasoning_content`) e H2 com o
   nome `reasoning` chegam as duas como `reasoning_content` com bytes: a ficha do AOS-507 não as
   separa uma da outra em produção, mas separa-as das restantes. H2 com `thinking` ou
   `reasoning_details`, e H5 (`refusal`), chegam SEM o campo: depois do proxy ficam iguais a H6
   («nada»). Só `reasoning_tokens` (H3) e o digest da forma as podem separar. Uma série com a
   ficha a dar `reasoning=nenhum` não exclui por isso H2 nem H5.
2. **O AOS-509 por esta rota.** `content` em partes e raciocínio em objecto nunca chegam ao
   gateway: o proxy dá 500 antes. `arguments` em objecto chega em string. A descodificação
   tolerante do AOS-509 serve uma rota sem este proxy, ou outra versão dele; por esta, o que
   muda é a leitura de `thinking_blocks` como raciocínio (os outros nomes ou são renomeados ou
   não chegam).
3. **Um 500 do proxy não é uma resposta recusada.** Não conta em
   `aos_model_response_rejected_total`: o turno falha com o status do proxy, como hoje.

## 5. Como repetir

```bash
bash scripts/ci/wire-live.sh                      # ou: make ci-wire-live
AOS_WIRE_LIVE_OUT=/tmp/wire-live.json AOS_WIRE_LIVE=1 \
  go test -run TestAOS508_ProxyReal -v -count=1 ./packages/platform/model-gateway
```

Sem Docker ou sem a imagem descarregada, o gate salta e di-lo (`AOS_SKIPPED_STEP`);
`AOS_WIRE_LIVE_REQUIRED=1` torna o salto vermelho. Não está no `run.sh`.
